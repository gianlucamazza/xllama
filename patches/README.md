# patches/

Patches against the pinned `llama.cpp` submodule. Every build that compiles
llama.cpp applies all of `patches/0*-*.patch`: the Linux CMake build (CLI and
host tests) and both UWP variants that compile ggml (`uwp/ggml-uwp.vcxproj`):
the shipping `unified` variant (`XLLAMA_USE_ORT=1` + `XLLAMA_USE_LLAMA=1`) and
the bench-only `llamacpp` variant. So host tests run the source the console
ships. `scripts/apply-llama-patches.sh` applies them in order and is idempotent
per patch; CMake configure runs it with `--check` and stops if one is missing.

The numbered series contains AppContainer guards, xllama-specific fixes and
backports. Each backport identifies its upstream source for the next pin review.

## Applying

```bash
git submodule update --init --recursive
./scripts/apply-llama-patches.sh           # idempotent; CI runs it for every build
./scripts/apply-llama-patches.sh --check   # what CMake configure runs
```

## Rebasing after a submodule bump

For the [#522 pin review](https://github.com/gianlucamazza/xllama/issues/522), inspect each cited upstream change on a clean candidate checkout before applying the local series. The script checks `git apply --reverse --check` first and counts a reverse-applicable patch as already present, including when upstream supplies the hunk. Changed surrounding code can also prevent either direction from applying. Compare the implementation and run the relevant regression before dropping a backport. Rebase any remaining xllama-specific behavior, including required AppContainer guards, into tracked patches.

Run `scripts/check-uwp-sources.sh` on the patched candidate before building both
UWP variants. It compares the llama, ggml/CPU and chat source directories with
the two MSBuild projects, including wildcard matches. Review new backend
directories and changes to the chat link closure separately. The upstream common
sources omitted from UWP are listed in `scripts/check-uwp-sources.py`.
