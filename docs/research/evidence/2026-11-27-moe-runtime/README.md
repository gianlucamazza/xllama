## Reproducing the CPU and storage checks

Use the source revision named for each result. For #668 initialize the pin, run `scripts/apply-llama-patches.sh` and its `--check`, configure `linux-test`, and build the test targets. `build/linux-test/tests/xllama-tests --test-case='moe_expert_cache:*'` must actually select the cache cases. Run `test-admission-allocation` and `ctest --test-dir build/linux-test --output-on-failure` as well. Optional checkpoint tests in the general suite need their own GGUFs.

The following uses the unmodified `test-backend-ops.cpp` from the pin and the patched shared libraries from the Linux test build. The input values in this upstream test are randomized. The operator, shapes and numerical criterion are fixed. Require successful exit and a successful CSV row for each type at each shape. Pin-native reference mode can reuse the same CPU implementation for this op. The deterministic scalar reference in #702 provides independent arithmetic. [Captured native rows](resident-cpu-operator.csv).

```bash
build_bin="$PWD/build/linux-test/bin"
c++ -std=c++17 -O0 -Illama.cpp/ggml/include llama.cpp/tests/test-backend-ops.cpp \
  -L"$build_bin" -Wl,-rpath,"$build_bin" -lggml -lggml-base -lggml-cpu -pthread -o build/test-backend-ops
OMP_NUM_THREADS=1 GGML_CPU_DISABLE_FUSION=1 build/test-backend-ops test -b CPU -o MUL_MAT_ID \
  -p 'type_a=(q4_K|q6_K|f32),type_b=f32,n_mats=4,n_used=2,b=0,m=(64,n=16|512,n=1),' -j 1 --output csv
```

At #696 run `python3 scripts/replay-moe-cache.py docs/research/evidence/2026-11-16-moe-24b-console`. Both traces describe 246 frames and 112,176 requests. A2 gives zero hits and 212,856,864,768 logical Reader bytes. B512 gives 39,330 hits and 138,343,145,472 bytes. Its request hit rate is 35.061%, its byte hit rate 35.006%. Physical SSD traffic, per-request device latency and lease intervals are unavailable. [#710](https://github.com/gianlucamazza/xllama/pull/710) attributes recorded elapsed Reader calls (including software time) to prefill and decode on the same two historical traces. LFU, ARC, byte-aware or per-layer eviction, selective residency, batching and prefetch need held-out workloads. Only an explicitly labelled offline oracle may use future events to define a replacement bound. [Original console evidence](../2026-11-16-moe-24b-console/README.md).

At the pinned CPU hook, thread 0 groups the original expert IDs and the first barrier precedes weight reads. The tiled path is reached before the generic expert pointer is formed. A native provider must qualify both execution paths or explicitly reject an unsupported path at admission. The generic loop has no per-expert barrier. A one-slot implementation must finish all readers of the current expert before reusing that slot for the next selected ID. Validate IDs before indexing, including in release builds. The terminal graph barrier follows the abort observation. Keep leases through actual completion on both exit paths. [Pinned worker loop](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/ggml/src/ggml-cpu/ggml-cpu.c#L1646).

The pin's tensor-data callback runs after allocation. A streamed provider needs a model-scoped descriptor before the loader's bulk allocation. Keep shared experts, router weights and other resident buffers on the ordinary path. The mutable lease cache requires a stable owner across load, decode and teardown; native worker zero is not sufficient to establish the coordinator's identity. Read original IDs and final weights with their actual GGML strides. No C++ exception may cross the GGML C interface. [Model loader](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/src/llama-model-loader.cpp#L1116) · [Router](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/src/llama-graph.cpp#L2158).
