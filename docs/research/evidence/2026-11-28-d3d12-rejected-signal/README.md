# D3D12 rejected queue marker, 2026-11-28

**FAILED on the synthetic Linux queue.** When a live queue rejects its marker after `ExecuteCommandLists`, the backend copies stale readback data, overwrites upload staging, and resets an allocator with an outstanding submission. A subsequent `run_now` returns success when the mock accepts its new marker, even though the allocator rejected the intervening reset. The accepted-marker device-removal control returns failure. [Captured output](receipt.txt) · [#714](https://github.com/gianlucamazza/xllama/issues/714) · [#743](https://github.com/gianlucamazza/xllama/pull/743).

## Reproduce

Run the following command in a Linux checkout containing commit `ce948e1036bad4843500409104c6481a09a1afbb`.

```sh
python3 docs/research/evidence/2026-11-28-d3d12-rejected-signal/replay.py
```

The script uses `git show` to read the four original function definitions and their fence header from that revision. It compiles the definitions with the queue double in a temporary directory outside the checkout. The recorded run used Python 3.12.14 and GCC 14.2.0 on Linux x86-64. The required tools are Git, Python 3 and a C++17 compiler. Set `CXX` to select a compiler executable. [Replay script](replay.py) · [Queue double](replay.cpp).

The double keeps submitted work outstanding when `Signal` fails, leaves the readback ring at a known byte value, and returns a failing HRESULT from an allocator reset while work is outstanding. The accepted-marker control advances the counter. The removed-device control returns `UINT64_MAX`. The fixture uses four-byte chunks to make two iterations observable with eight bytes of data. The product uses an 8 MiB staging ring. The counts record calls into the mock. Windows D3D12, debug-layer output, package identity, GPU execution, elapsed recovery time and working-set measurements are **NOT_RUN**.

## Recovery gate

A recovery candidate needs an owner for each object the submitted list can reference, including allocators, descriptor heaps, root signatures, PSOs, query heaps, scratch, mapped rings and graph buffers. Until completion or confirmed device removal, the backend must exclude new submissions and CPU reads or writes through aliased pages. A bounded retry may enqueue a fence marker behind the existing work. Load, tensor transfer and CPU-tail callers must observe a terminal failure before publishing output. Capture retained bytes and verify a fresh independent request. [Recorded acceptance criteria](https://github.com/gianlucamazza/xllama/issues/714).

Microsoft requires GPU completion before allocator reuse. A live device reports `S_OK` from `GetDeviceRemovedReason`. Direct3D creates one device per adapter in a process, so forced removal can also affect other owners. Exercise the candidate with the Windows debug layer, then repeat with an identified Xbox package and a CPU reference.
