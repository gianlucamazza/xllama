# Distributed inference threat model and failure contract

**Verified** refers to the linked source. **Proposed** describes an acceptance condition. **Unverified** applies to every multi-console control until a run supplies a receipt. This analysis extends the [shipping threat model](https://github.com/gianlucamazza/xllama/blob/bc53c3d6dfb202db6a14d780643db6f9f262f8ea/docs/audit/excellence/standards-2026-11-27/security.md) and the [private disclosure policy](https://github.com/gianlucamazza/xllama/blob/bc53c3d6dfb202db6a14d780643db6f9f262f8ea/SECURITY.md).

## Existing boundaries

- **Verified.** The shipping LAN HTTP API is opt-in, unauthenticated and foreground-only. The Developer Mode manifest requests private-network client/server access. The Store manifest requests Internet client access only. Bounded HTTP framing, connection slots and a single local compute permit protect the existing request path. An RPC parser would be a separate entry point with its own resource and failure behavior. [HTTP contract](https://github.com/gianlucamazza/xllama/blob/bc53c3d6dfb202db6a14d780643db6f9f262f8ea/docs/api-endpoint.md) · [Developer manifest](https://github.com/gianlucamazza/xllama/blob/bc53c3d6dfb202db6a14d780643db6f9f262f8ea/uwp/AppxManifest.xml) · [Store manifest](https://github.com/gianlucamazza/xllama/blob/bc53c3d6dfb202db6a14d780643db6f9f262f8ea/uwp/AppxManifest.store.xml)
- **Verified.** At the integrated pin, upstream describes RPC as an insecure proof of concept. HELLO checks version and transport capabilities. Several connect, handshake and response failures can abort the calling process. Optional tensor-file cache lookups use FNV, a non-cryptographic content hint. These mechanisms provide neither peer authentication nor model provenance. [RPC warning](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/tools/rpc/README.md) · [HELLO and dispatcher](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/ggml/src/ggml-rpc/ggml-rpc.cpp#L347-L360) · [failure paths](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/ggml/src/ggml-rpc/ggml-rpc.cpp#L537-L569) · [weight cache](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/ggml/src/ggml-rpc/ggml-rpc.cpp#L712-L739)
- **Verified.** Microsoft documents TLS client negotiation on WinRT StreamSocket. Server negotiation on a socket accepted by StreamSocketListener is unavailable through that API. Same-host AppContainer IPC has its own restrictions. A different host reaching the Xbox HTTP listener establishes neither a same-console sidecar path nor an encrypted Xbox hop. In the co-located design, address the local compute device in-process. **Unverified:** an authenticated data-plane termination on the target UWP package. [Microsoft networking](https://learn.microsoft.com/en-us/windows/apps/develop/networking/networking-basics#secured-connections) · [UWP IPC](https://learn.microsoft.com/en-us/windows/uwp/communication/interprocess-communication)
- **Proposed trust domain.** One operator controls the coordinator, workers, switch, local storage and fixture. Every participating machine can learn data it handles. Treat prompts, activations, KV, logits and outputs as potentially sensitive, and replicated weights as licensed assets. Developer Portal credentials belong to deployment only. Record source/package/model digests, counters and failure codes. Omit tensor bytes, prompts, raw device addresses and credentials from shared receipts. A trusted or encrypted connection does not establish a peer's computational honesty. [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)

## Admission, confidentiality and containment

| Boundary and risk                                                               | Proposed control and acceptance evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Operator ↔ service, accidental public exposure or excess authority              | Independent, default-off research selection, visible run state, explicit stop. For an approved LAN experiment use operator-owned, isolated peers, manually configured addresses and non-sensitive fixtures. Verify bind scope and both legs of a gateway before admitting work. Exclude public listeners, port forwarding and automatic discovery. Expose only inference operations needed by the experiment. Record setup/stop receipts.                                                                                                                                                                             |
| Coordinator ↔ worker, impersonation, unauthorized use, observation or tampering | A private capability, IP allowlist and HELLO describe reachability. For any wider operating scope, require each peer to prove an enrolled identity, authorize its role/model operation and protect bytes on every required hop. Prefer an established mutually authenticated transport with validation and revocation. Test identity mismatch, expiry, revocation and unexpected peer rejection before allocating. TLS on the client-facing PC leg leaves a plaintext PC→Xbox leg exposed. If target termination cannot be demonstrated, retain isolated lab scope. [TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446) |
| Coordinator/worker ↔ model, mismatch or substitution                            | Record full model and shard SHA-256, release/source identity, tokenizer/template/config, quantization, tensor inventory, and model licence on every weight holder. Check against an operator-approved manifest before opening the session. Cache keys alone prove neither authorization nor integrity. Start with upstream cache disabled, then validate an opt-in bounded cache, disk quota, eviction, version/digest isolation and wipe on retirement.                                                                                                                                                              |
| Remote peer ↔ native graph/tensor parser, crashes or potential code execution   | A network peer can influence native allocations and graph operations. Treat code execution as an impact to contain, not a vulnerability finding. Pre-allocate only after checked type/shape/stride/size and offset bounds, model/device constraints and aggregate quotas. Restrict the experiment to known graphs/devices and trusted fixtures. Exercise range validation offline on harmless fixtures. For DC-3 use a disposable unprivileged desktop process with an outside watchdog. Review upstream fixes and investigate unexpected faults through private reporting.                                           |
| Session/transport ↔ memory, disk and accelerator, exhaustion or service denial  | Bound queued sessions, bytes in flight, tensor/frame/graph size, context, graph work, temporary copies, resident weights/KV, cache and disk by actual node budgets. Charge in-flight and duplicated storage. Set connect, operation and session deadlines plus bounded cancellation cleanup. Deny excess work before allocation and retain the local compute permit until work has quiesced. Record peak, rejects, release and ability to serve fresh work.                                                                                                                                                           |
| Device ↔ operator, incompatible runtime, stale results or dishonest computation | Record exact executable, protocol, backend, patch set, model digest, shape and resource declaration. Exclude mismatch before placement. A protocol version still requires semantic and numerical checks. Bind results to one attempt and ordered token position in the coordinator; discard stale or duplicate results. A participating peer may read or corrupt intermediate data even with transport protection. Scope this research to trusted peers and test parity against the resident reference.                                                                                                               |

## Failure handling

| Event                                                           | Required behavior in a future experiment                                                                                                                                                                                                         | Evidence needed to pass                                                                                                                                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Busy replica or full coordinator queue                          | Refuse promptly with the existing busy semantics, bound pending requests and preserve session affinity. Retry only when admission is known to have failed.                                                                                       | Counts for attempted, accepted, busy and failed requests, peak queue size and recovery.                                                                                                                         |
| Link loss, timeout or worker suspension                         | Stop admitting work for that peer. Fail the affected sharded session, release surviving allocations when safe and discard partial KV and incomplete output. Mark an interrupted stream clearly. A same-model replica can accept a fresh request. | Disconnect during load, prefill and decode. Record bounded client-visible failure, cleanup time, memory after a fresh session and successful new local/replica request.                                         |
| Coordinator crash or Xbox leaves foreground                     | Workers enforce bounded ownership/cleanup. Stop issuing work against stale sessions. On restart revalidate peers, budget, model identity and placement. Game/foreground state is part of the receipt.                                            | Coordinator loss and restart, recovery from a suspended/terminated worker, no late output passed to the new session. [UWP lifecycle](https://learn.microsoft.com/en-us/windows/uwp/launch-resume/app-lifecycle) |
| User cancellation or uncertain completion                       | Quarantine the run until work stops or a disposable host child is torn down. Do not replay a partially emitted generation or share its KV. Begin an explicit fresh attempt only after cleanup.                                                   | Timestamp stop acknowledgement, permit release and successful local baseline. A stuck or aborted integrated console process fails this gate.                                                                    |
| Wrong model/protocol, invalid result, out-of-budget reservation | Reject before dispatch when detectable, otherwise fail that attempt and withhold further output. Mark a previously streamed prefix incomplete. Remove the suspect node until compatibility and budget are rechecked.                             | Controlled fixture mismatch, bounded admission refusal, parity failure reporting and repeatable re-entry.                                                                                                       |

## Gate decisions

- **DC-0–1, Proposed.** Documentation and an offline calculator can complete on the host. An approved DC-1 probe records the network boundary, exact packages, foreground state, endpoints and teardown. Use synthetic traffic. Broadening manifest capabilities or opening a public listener falls outside this gate.
- **DC-2–3, Proposed.** Replicas retain the existing single compute owner per console. A separate desktop-only RPC spike starts on loopback with a synthetic model, cache off and process containment. Before any isolated multi-host RPC test, require explicit approval, identified participants, controlled interfaces and proof that experiment traffic cannot reach other peers. Fail this gate if ordinary loss can terminate the normal console path.
- **DC-4–6, Proposed.** Admit a console graph only after target-compatible APIs, an independently approved isolation or recoverable-error design, per-node budgets, foreground failure behavior and hash/precision compatibility are demonstrated. Keep RPC and HTTP trust decisions independent.
- **DC-7–8, Proposed.** Extend ownership and teardown to expert replicas, bounded SSD leases and remote results. Require original router IDs/weights and counter-based evidence that a late result or stale cache entry cannot enter the next decode. Apply the single-node MoE prerequisites before a hybrid trial.
- **DC-9, Proposed.** Before broader deployment, demonstrate independently reviewed protection on every required hop, least privilege, consent, lifecycle, cancellation, bounded resources, identity/version handling, numerical integrity and recovery on each intended target. If a required control is missing, record **no-go** for that scope. A successful isolated trial is evidence for its stated trust domain only.
