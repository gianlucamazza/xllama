# Stage gates and stop decisions

**Proposed.** The maintainer records a separate go, hold or stop for each requested experiment on [#687](https://github.com/gianlucamazza/xllama/issues/687). Device time, a pin change, deployment and release each have their existing owners. DC-2 and desktop DC-3 can be assessed independently. DC-4 can proceed without a positive HTTP throughput result if its distinct capacity objective and its own prerequisites hold. Each test uses the [common protocol](protocol.md), the [threat model](security.md) and an explicit fixture/target list.

## Two-node decision record

Before running DC-1 record the operator, enabled mode, deliberate network isolation, devices and package. Freeze the actual payload sizes and directions, resource reserve, failure deadline and output format. Replace the modeled link values with directional observations. For DC-2 record the offered workload, admission limit, p95 objective and quality/termination policy before collecting candidate data. For DC-4 separately require a trusted packaged worker, a recoverable failure or demonstrated isolation, a single-node reference and actual remote execution. These questions may receive different decisions on the same hardware.
