# Quantitative feasibility

**Estimated.** The [calculator](../../../scripts/model-distributed-inference.py) estimates working-set fit, serial decode, independent-request throughput and cost under explicit placement assumptions. All numbers below are synthetic. The program reads no checkpoint, starts no listener and requires only the Python standard library. A mathematical fit on 16 or 32 workers is particularly different from a realizable pinned RPC configuration: the inspected pin has a 16-device interface limit and its CLI rejects 16 explicit split ratios. Independent request replicas do not share a llama.cpp device list.

**Measured, separate reference.** The local [benchmark record](../../benchmarks.md) and [model matrix](../../model-matrix.md) contain Series S results for named checkpoints. The latter records a resident 8B MoE at a different quantization and an allocation failure for a larger artifact. Measurements for one checkpoint, quantization, package or mode do not calibrate these synthetic shapes. Retrieve the device and App/Game evidence from the [platform constraints](../../uwp-constraints.md). The source for actual K-quant block layouts is the [pinned GGML definition](https://github.com/ggml-org/llama.cpp/blob/d81235049384534c167caea52b85a694f6103d14/ggml/src/ggml-common.h).

## Reproduce

Run at repository root. The full sweep writes 864 CSV cases, spanning 1, 2, 4, 8, 16 and 32 worker nodes, six shape classes, three input profiles and every applicable strategy. One external coordinator is additional to the worker count where specified. No sweep output belongs in the console benchmark archive.

```sh
python3 scripts/model-distributed-inference.py > /tmp/dc-estimates.csv
python3 scripts/model-distributed-inference.py --scenario realistic --model 8 --family dense --strategy pipeline --nodes 1 2 4
python3 scripts/model-distributed-inference.py --scenario realistic --model 8 --strategy hybrid --family moe --nodes 2 --set hit=0.9 --expert-legs 1
python3 scripts/model-distributed-inference.py --scenario realistic --model 8 --family dense --strategy replica --nodes 1 2 --shape params_b=3 --shape hidden=3072 --shape vocab=32000
python3 -m unittest discover -s tests -p test_distributed_inference_model.py
```

Record the source commit with the CSV. Each row names the scenario, actual parameter count, shape class, layout and overrides. A blank rate, cost or efficiency is intentional. `budget` means at least one worker exceeds its local process cap. `layout` means the requested discrete mapping or lease cannot be represented. `fits` means the modeled steady-state worker budget passes, conditional on adequate external host memory. Peak loading RSS, allocator fragmentation, coordinator working set, operator coverage, real transport dtypes, numerical parity, availability of concurrency and thermals still need measurements.

## Mechanics

Let `P` be total parameters, `q` effective bits/parameter, `L` layers, `H` hidden size, `V` vocabulary, `C` cached tokens, `G` KV heads, `d` head dimension, `S` live sequence slots and `bK` KV bytes per element. Per-node app limits are independent.

- Whole weight storage is `W = Pq/8` bytes. Each of two untied vocabulary tables occupies `V H q/8` bytes. The remaining weights are partitioned into whole layers. One local embedding lookup reads one row; the final vocabulary projection reads the whole output table. At multiple pipeline stages the external CPU owns the input table and sends the input embedding. The last worker owns the output table. A coordinator holding source weights during load can need far more than the reported `host_floor_gib` (input table plus the larger of one embedding or logit row). Measure source/mapped/committed bytes and cold-load staging independently.
- Per-layer KV is `2 C G d bK` bytes per sequence. A worker with `l` layers budgets `S l` times that plus assigned resident weights and reserve. Reserve includes non-model RSS, scratch, copy buffers and margin. The sum of `cap − reserve` across workers is a placement ceiling. The largest rank and endpoint ownership govern fit. The default allocates near-equal whole layers, extra layers to the earliest stages. The calculator supports manual unequal placement.
- For each stage, decode is `max((active weight reads + KV reads/writes)/effective bytes per second, FLOPs/effective FLOP per second) + l × launch overhead`. One token reads a full current KV history and appends one entry per layer. The arithmetic proxy is two FLOPs per active weight plus approximately `4 l H C` attention FLOPs. MoE uses its shared weights plus `top_k/E` of routed weights. This roofline omits implementation-specific intermediate tensors, CPU/GPU dispatch and overlapped cache effects. Raw nominal memory bandwidth is unsuitable as a sustained kernel input.
- With `A = H × activation bytes`, an external-coordinated pipeline of `N>1` stages moves `legs × (N−1)A + A + 4V` payload bytes per decode token. The default uses two legs for a remote-to-remote boundary (GET→coordinator→SET), one input embedding and a complete logit row to the sampler. A one-leg direct path is a sensitivity case. Serialized transport time for `D` bytes and `U` exchanges is `8D/B_tcp + 2D/B_copy + U(RTT + sync)`, with consistent units. Actual graph scheduling can introduce more transfers and synchronization. The single-stage independent replica/EP/TP variants assume local sampling. Client HTTP, prompt, SSE, headers, retransmits and graph control payloads are outside the tensor counters; capture them separately.
- For single-sequence decode, pipeline stages and transfers add. An independent stream cannot send its next token in advance of sampling the previous output. For `S` independent streams an upper estimate of steady throughput is the minimum of `S/serial latency`, `1/slowest compute stage time` and the full-duplex coordinator NIC ceiling. Only `pipeline` accepts extra active slots. The cap accounts for each slot's KV. Scheduler serialization, connection contention and bubbles can reduce the rate. For independent complete replicas, estimated aggregate rate is the sum over independently busy workers; one request retains its local latency. Queueing, batching and affinity need service-level measurements.
- A two-all-reduces-per-layer ring sends `2L × 2(N−1)A/N` bytes **per rank** and receives the same amount. There are `2L × 2(N−1)` sequential rounds, each charged `RTT/2 + sync` plus wire/copy time. Compute assumes ideal layer-weight sharding, replicated endpoints and at least one whole KV head per worker. Uniform head mappings that cannot be divided are marked `layout`. The topology is a counterfactual collective model, not a description of GGML RPC row split. For context sharding, a remote KV block has `2 C_block G d bK` bytes per covered layer; compare moving that block per query with moving query vectors/partial attention statistics. The latter still needs an exact softmax merge and measured kernel/collective scheduling. The CSV does not claim a context-parallel runtime.
- For expert parallelism the home rank holds the shared layers, router, KV and both vocabulary tables. Whole expert IDs are assigned per layer to group members. A group with `g` ranks has at most `ceil(E/g)` experts per owner/layer. Default expected remote selections are `L × top_k × (1−1/g)`; set `--remote-fraction` from a trace to account for locality/replication. Each selection sends an activation and returns a contribution, with one RTT for a direct exchange or two for a relay. `--expert-legs` defaults to two independently of the pipeline topology. Expert execution and reads are serialized; the estimate assumes unchanged gate IDs, scores and reduction order. Simultaneous experts, hotspot skew and coalescing can change delay and staging requirements.
- Hybrid divides the workers into contiguous pipeline stages and assigns `--group` expert ranks to each stage (two by default). The solid-state backing stores all expert weights. Only the smaller of each rank's shard and its bounded cache is resident. One layer expert must fit for a single serialized lease. For equal-size experts of size `X`, expected SSD traffic per token is `misses × X`, with `misses = Σ l × top_k × (1−hit)`. Per miss add `X/B_ssd + read_latency`. A full warm shard has zero modeled misses. A given byte hit rate, physical layout, read granularity and cache residency must be consistent; skew can give different hit rates per rank. Where the deployment requires every worker to access the full GGUF, budget up to the full artifact on **each** disk. This is an ideal placement hypothesis, with independent OOC/parity gates.
- Prefill has a different critical path. A prompt microbatch of `m` tokens moves about `mA` bytes per cut/leg and can amortize fixed messages while increasing peak staging. Example: 512 tokens × 4,096 × 2 bytes × two relay legs costs 8 MiB or 83.89 ms serialization alone at 800 Mbit/s for one cut. Requesting logits for every prompt token can add `m × 4V`; last-row-only adds `4V`. TTFT also includes queueing, tokenization, cold load, graph setup, prefill, first sampling and client delivery. Never derive TTFT/prefill tok/s from the decode rows.

## Sensitivity and break-even

- Across the optimistic/central/pessimistic four-worker dense 8B pipeline, estimates are 4.73/2.64/1.46 tok/s and €13.77/26.46/52.22 per million tokens. With two workers at central values, changing only goodput from 800 to 350 Mbit/s takes network time from 8.36 to 15.26 ms and rate from 2.66 to 2.61 tok/s. Reducing effective worker reads from 13 to 8 GB/s gives 1.65 tok/s. Cold start, long prefill and large logits can shift this balance.
- For one selected layer expert, compare resident remote round-trip time `t_r` with `(1−h)(X/B_ssd + latency)` for a local bounded cache. Identical kernels cancel in this simplified comparison. The threshold is `h* = 1−t_r/(X/B_ssd+latency)`; remote wins only if `h < h*` and the remote owner remains resident. The example has 4.323 ms per local miss vs 0.879 ms direct or 1.757 ms relayed. Thresholds are approximately 80% and 59% respectively. Raising the hybrid hit prior from 0.60 to 0.90 drops its SSD term from 221 to 55 ms/token. Router semantics must stay fixed while testing the branch.
- Pipeline latency improves over a fitting baseline only when saved local work or eliminated disk stalls exceed added transfers plus synchronization. For tensor splitting, compare saved compute with the entire ring critical path. For request replication, useful demand must exceed single-worker capacity at the same tail-latency target; queues can dominate before throughput saturates.
- Let `u` be utilization, `R` occupied-cluster output tok/s, `P_a/P_i` aggregate active/idle W, `K` total capex, `Y` amortization years, and `p` €/kWh. Active J/token is `P_a/R`. Fully allocated €/million = `10^6 × [K/(8760Y) + (u P_a + (1−u) P_i)p/1000] / (3600uR)`. Idle equipment remains powered in this scenario. This excludes operations labor, failures, discounts and embodied energy. At 10% utilization the two-worker dense pipeline rises from €14.87 to €40.85/M. If the capital is already sunk (`--set node_eur=0 --set coord_eur=0`) it is €7.15/M at 35%.
- Illustrative standalone PC comparison: use the same dense 8B with `--nodes 1 --strategy replica --set cap_gib=24 --set reserve_gib=2 --set mem_gbs=35 --set gflops=150 --set node_eur=1000 --set active_w=100 --set idle_w=18` on the central scenario. Its model gives 7.26 tok/s, 13.8 active J/token and €5.59/M. At the specified PC cost and power, a **measured** rate above 2.73 tok/s would beat the two-worker illustration's €14.87/M, assuming identical utilization/quality. Competing with a single PC on new purchases is unproven; a capacity-only win, donated hardware and existing equipment must be priced separately.
- For heterogeneous pipelines use `--strategy pipeline --model 8 --family dense --scenario realistic --streams 2 --layout /tmp/stages.json`. An example JSON array is `[{"layers":9,"cap_gib":4,"mem_gbs":8,"gflops":45,"node_eur":250,"active_w":75,"idle_w":12},{"layers":23,"cap_gib":8,"mem_gbs":22,"gflops":130,"node_eur":600,"active_w":110,"idle_w":16}]`. Changing a 16/16 cut to 9/23 gives 3.59→6.14 aggregate tok/s in this shape, paying higher memory on the faster node. The separate coordinator remains budgeted. Real Series X and PC coefficients must come from equivalent local workloads.

**Proposed decision.** Use the first two-worker experiment to replace the link, compute, resource and copy priors, and the first fitting replica run to establish latency and throughput references. Attempt a single-model trial only with a verified per-rank and coordinator **load and steady-state** budget, measured link trace and numerical control. Publish the measurement inputs, predictions, observed residuals and wall-power integration interval together.
