# Distributed inference literature and implementation review

**Evidence scope.** Verified describes an upstream implementation, vendor specification or paper. Measured labels a result reported by its authors and identifies the hardware. Proposed labels a reuse decision or an experimental comparison for xLlama. Xbox UWP support is **Unverified** for every multi-node runtime in this review. Windows means a desktop process unless a source explicitly identifies an Xbox package. A published paper, a permissive software licence and a compatible checkpoint format answer different questions.

## What carries over from DGX Spark

**Verified.** Each Spark has an Arm CPU, a Blackwell GPU and 128 GB of local LPDDR5x unified memory rated at 273 GB/s. Its 10 GbE RJ45 and its ConnectX-7 QSFP connections are distinct interfaces. NVIDIA specifies up to 200 Gbit/s per QSFP port and documents RoCE interfaces, direct cables and switched setups. Local CPU/GPU memory coherence ends at the node boundary. A distributed framework decides what each process owns and exchanges. Dividing nominal 200 Gbit/s by 1 Gbit/s gives a 200:1 line-rate comparison. Application throughput must be measured. Spark can use RoCE for RDMA operations on registered buffers. Each process still owns its local address space, and the Xbox experiment has no established RDMA path. [Hardware][spark-hw] · [NIC topology][spark-net] · [multi-node instructions][spark-stack]

**Proposed.** Establish each host's baseline, characterize the actual peer link, place weights explicitly and measure an application workload. Use a switch for the Xbox wired test. A logical ring requires only IP reachability. The GPU, CUDA, NCCL, RoCE, QSFP ports and vendor software entitlements are properties of specific Spark configurations. The Xbox experiment must establish its own network, host-copy and memory budgets. [Spark software and licensing][spark-sw]

A low cost means a comparator or schedule outside the console runtime. A medium cost includes an opt-in host build and a separate packaging assessment. A high cost means adding substantial dependencies or replacing the engine. “No documented bridge” means the cited project does not provide an xLlama GGML device or D3D12 adapter.

## Which algorithm changes the bytes on the wire?

The following are techniques with multiple implementations. They have no common binary dependency, software licence or operating-system target. The cited papers provide comparison methods. The table above names concrete runtimes where applicable. None of the papers records an xLlama/Xbox package or a D3D12 inter-node run.

For independent requests only prompt/output traffic crosses the cluster.                                                              | First aggregate throughput comparison. Introduce controlled concurrency, record queueing and affinities, and enforce admission limits. Batching depends on the existing worker contract.                                                                                            |
| Pipeline parallelism. GPipe is a **training** result. Petals provides the **inference** precedent. [GPipe][gpipe], [Petals][petals-paper]                                                                                                                                                                        | Adjacent layer groups pass the hidden activation at a cut. Resident stage-local KV avoids a per-token transfer of the entire prefix. One stream still serializes token dependencies.            | Choose contiguous layers by measured time and memory. ## Published evidence and limits

- **Measured by the authors.** The prima.cpp repository reports 674 ms per generated token for Llama 3-70B in its heterogeneous home setup. Table 1 identifies an M1 Mac, two Linux PCs and a phone. Device selection can exclude workers. Table 2 identifies the tested result, and the ICLR paper reports speculative-decoding results separately. Keep configuration, precision, hardware and decoding method attached to any comparison. [Experiment tables][prima], [ICLR paper][prima-paper]
- **Verified.** The Petals evaluation includes Llama 2 (70B) and BLOOM (176B) paths over the Internet. The comparison baseline is offloading in the authors' setup. The paper demonstrates that a layer boundary can be practical on a slow link under its hardware, partitioning and trust assumptions. [NeurIPS paper][petals-paper]
- **Proposed.** For an economic decision, benchmark a PC alone at the same model, context, quantization, concurrency, wall power and latency objective as the cluster. Treat acquisition of already-owned consoles separately from new hardware and count coordinator, storage and switch energy. A faster heterogeneous cluster may simply be using the fastest PC. Hold that machine out in one ablation.
