## Delivery rules for follow-up work

- One behavior change per PR; preserve other worktrees and do not edit the submodule
  in place. Dependency fixes remain possible when evidence places the defect there.
- For structural decisions, propose Context / Decision / Consequences / Alternatives,
  obtain acceptance, then implement. Supersede rather than rewrite accepted ADRs.
- Update each contract's owning document in the same PR. This dated audit remains
  historical; record resolution links rather than retroactively changing observations.
- Run focused regression tests, then applicable project gates. UWP changes require
  MSVC CI plus exact-package device evidence; Linux success is not a substitute.
- Neither backlog priority nor an audit finding authorizes publishing, signing,
  changing Store identity, or accepting an ADR on the owner's behalf.
