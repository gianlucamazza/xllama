The following is an extended technical overview of heterogeneous computing on game consoles. Read it carefully and then summarize the three most important trade-offs it describes. Modern game consoles occupy an unusual position in the computing landscape. They combine a semi-custom system-on-chip with a unified memory architecture, a fixed hardware target, and a heavily curated operating system. The eighth and ninth generations of consoles converged on x86-64 CPUs paired with RDNA-class GPUs, sharing a single pool of GDDR6 memory. This unified memory design eliminates explicit host-to-device copies that dominate discrete GPU programming, but it also means the CPU and GPU contend for the same memory bandwidth, and the memory controller arbitrates between latency-sensitive CPU traffic and throughput-oriented GPU traffic. For workloads that stream large amounts of data, such as the weight matrices of a neural network, this arbitration becomes the defining performance constraint. Large language model inference decomposes into two phases with very different hardware profiles. The prefill phase processes the entire prompt as a single batch: it is a sequence of large matrix-matrix multiplications, embarrassingly parallel, compute-bound on most hardware, and an excellent fit for wide SIMD units and GPU compute. The decode phase generates one token at a time: each step reads every weight of the model once and performs comparatively little arithmetic on it, making the phase memory-bandwidth-bound and latency-sensitive. A hardware platform can therefore excel at one phase and disappoint at the other. Wide GPUs with high bandwidth dominate prefill, while decode throughput is capped by how fast a single agent can stream the weights, and by any fixed overhead paid per generated token. Per-token overhead deserves particular attention on portable graphics APIs. Frameworks that lower neural network graphs onto graphics command queues must record, submit, and synchronize command lists for every decoding step. On a discrete desktop GPU with a mature driver this overhead is amortized by sheer compute throughput; on a console GPU running inside a sandboxed application environment, each submission crosses additional validation layers, and the accumulated fixed cost can exceed the useful compute by an order of magnitude for small models.
