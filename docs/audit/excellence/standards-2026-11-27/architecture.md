## Architecture and repository boundaries

Review baseline `16a58a995ded56bc40e38a9e2234c490681d41b5`. Static inspection and host execution cover different questions. The include walk examined 153 first-party headers and translation units in `include/xllama`, `src`, and `uwp`. It resolved 345 unique literal quoted-include edges, with no directed cycle or core-to-UWP application edge. It omits generated headers, macro includes and system includes. MSBuild and CMake explicitly list 37 common bridge source files. The one extra CMake bridge file is the Linux CLI parser. Build-source comparison alone does not establish equivalent binaries.

The corrective decisions draw on the [C++ working draft’s filesystem grammar](https://eel.is/c++draft/fs.path.generic), [shared ownership exception guarantees](https://eel.is/c++draft/util.smartptr.shared.const), [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) and [CMake target usage requirements](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html). C++ language/library rules and the community guidelines have different authority. The existing UWP build remains the product build.
