### Repeatable device procedure

1. On an authorized console host use the shipping source checkout, CI run and unified artifact identified in the receipt. Verify all published checksums and record package family, revision, console SKU, OS, App/Game designation, active knobs and models. Compare hash to the released MSIX before install.
2. Use a test profile and the in-place upgrade path in `docs/console-validation-runbook.md` and `docs/install-release.md`. Record listings before and after. Preserve data and retain the known-good artifact. Downgrade is subject to package revision restrictions.
3. Load the operator's external Device Portal environment. Run `scripts/validate-console.sh all`, `ORT_MODEL=smollm2-360m-cpu-int4 scripts/validate-api.sh all`, and `scripts/validate-api.sh disconnect`. Record gate exit status, logs, health and recovery times. With default GPU knobs run `scripts/bench-d3d12-selftest.sh --out <fresh-file>`. Record and restore gate-owned state. A future changed release needs its own run.
4. Use separate candidate/CPU/GPU performance runs, identical model/prompt hashes and sampling, with warmups and repeats, memory telemetry and raw rows per backend. Include pin, commit and run ID. Locate future receipts under a unique `bench/results/` directory, redact host identifiers and credentials, checksum receipts. Series X, Series S, Linux and emulated results are separate.
