## Functional status and alternatives

The Series S release receipt covers the shipped unified configuration. Linux exercises the GGUF path; it cannot qualify ORT/DML under AppContainer. The catalogue withdrawal filter explicitly removes qwen25-coder-3b; historical performance rows remain evidence. Additional model types are proposals (#555–562); newer upstream architectures await #522. DirectML component availability or a successfully loaded file is insufficient for promotion. Record model revision, weights and tokenizer identity, quantization, template, load/accuracy checks, memory and target-device evidence. Keep trained adapters and their base identity tied to the training lane. The manifest comment calling GGUF CPU-only conflicts with its GPU-layer data; correct it through the catalogue owner's active PR after convergence.

GGUF and llama.cpp are upstream implementation contracts, ONNX is a model interchange specification, the OpenAI API is a provider contract, and the local /health fields are xllama extensions. OpenAPI 3.1 plus JSON Schema can document supported operations and constraints, but should be checked against positive and negative handler fixtures. Defer a hand-maintained full-provider schema. Use the actual client journey before selecting an agent-framework adapter. Retain plain HTTP on the documented trusted LAN; optional authentication or TLS needs an operator use case and target-SKU testing. Server schedulers from vLLM or SGLang, Ollama/LM Studio management surfaces and MLC/ExecuTorch backend replacements would each add a second policy or runtime without solving a measured failure here. Their behavior can inform external client tests.
