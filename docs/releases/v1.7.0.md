## Changes since 1.6.0

### Chat and models

- LFM2.5-350M remains the first-launch default. LFM2.5-1.2B uses the GGUF
  Direct3D 12 backend by default; other catalogue GGUF models use the CPU.
  Current model choices and measured results have one home in the
  [model guide](../model-selection.md), [model matrix](../model-matrix.md)
  and [benchmark receipts](../benchmarks.md).
- Qwen2.5-Coder-3B is withdrawn from the catalogue and cannot be downloaded
  in-app or through `/api/pull`. Historical research results remain labelled
  in the benchmark documentation. Qwen2.5-Coder-1.5B is the catalogue coding
  option. Check each model's licence before use.
- Catalogue files have individual content pins and weight/sidecar roles.
  Updating a sidecar preserves verified weights; an incomplete GPU model
  remains on CPU until its required files are ready (#372, #377, #388).
- GUI and API share one resident session and one compute slot. Heavy jobs
  receive a visible busy state or HTTP 503 while another operation runs.

### LAN API

The API is opt-in, off by default and has no authentication. Enable it only
on a trusted network. The [API contract](../api-endpoint.md) owns the routes,
limits and request examples.

- OpenAI-compatible streaming returns incremental chat chunks, finish/usage
  information and the completion marker. Disconnecting cancels generation.
- Tool schemas produce client-side proposals; the app does not execute tools.
  Replay accepts templates that ignore tool definitions, and reasoning is
  separated from assistant content, including truncated thoughts (#383, #387).
- Framing, generation parameters and prompt budgets are validated before
  loading a model. Missing local models return 404. Prompt usage includes
  the full prompt even when a KV prefix is reused.
- The console header shows endpoint activity while the API is enabled.

### Images and training

- SD-Turbo image generation retains the **Powered by Stability AI** credit.
  Attribution and licensing are documented in the
  [app guide](../using-the-app.md) and shipped [NOTICE](../../NOTICE).
- The first-party diffusion export toolchain uses patched dependencies,
  preserves native CLIP tokenizer files and prepares a separate DirectML
  deployment profile without changing the host parity reference (#378,
  #412, #413). True process lifetime peak working set is recorded separately
  from sampled private working set (#407).
- Isolated CPU host LoRA training uses a hash-locked environment and rejects
  unpinned/system-package fallbacks (#410). Checkpoint-supplied custom Python
  code is disabled (#401). See [training setup](../../training/README.md).
- The dated [execution ledger](../audit/excellence/execution-2026-11-07.md)
  records host training, runtime adapter, device-training and first-party
  diffusion qualification trials. Each trial is bound to its own package;
  it does not replace final-release package acceptance.

### Diagnostics and evidence

- The optional debug dashboard reports actual resident-model, LAN and
  inference readings; unavailable sources remain explicit (#357).
- Prefill/decode progress and the stall watchdog help identify hung runs.
- Console training and TAESD harnesses require fresh scoped results (#408,
  #381). File uploads reject transport, HTTP and Device Portal payload
  failures consistently (#415).
- Text benchmark hardware labels are explicitly operator-declared, separate
  from independent device observations (#404). Non-finite/invalid benchmark
  rows and malformed provenance metadata are rejected (#396, #399).
- Dependency monitoring covers both host toolchains. Scanner skips and
  qualification limits remain explicit in their receipts.
