# xllama v1.9.0

Independent project, not affiliated with or endorsed by Microsoft. Xbox and
Xbox Series S|X are trademarks of the Microsoft group of companies.

This Developer Mode release admits a GGUF session on its real memory cost and
lifts the fixed 8192-token context for GGUF models, makes long prompts
interruptible, and extends the LAN API with discovery, separate reasoning and
token accounting. The catalogue `n_ctx` values are unchanged.

## Sessions and memory

- A GGUF session is admitted before any weight is read. llama.cpp's no-alloc
  dry run sizes weights, KV and compute buffers, and a model that would not
  fit the app's memory limit fails with an `insufficient memory: …` breakdown
  instead of inside an allocation (the LAN API answers `400`).
- A GGUF session opens at its requested `n_ctx`, capped at the context the
  model was trained with, instead of a fixed 8192. ONNX sessions keep the 8192
  cap. The chat UI and the LAN API budget prompts against the context the
  session actually opened with.
- Stop and the stall watchdog now end a GGUF prefill inside its batch, not
  only between 2048-token batches (up to about 90 s on a 3B model).
- A long chat past `n_ctx` evicts whole turns, never half a message.
- Hybrid models (LFM2, Granite-4.0-H) keep a small partial-state prefix
  checkpoint instead of a full state copy, and it survives a conversation
  saved to and restored from disk.
- Images no longer fail next to a large resident chat model: the chat
  session is released only when the image pipeline would not fit beside it.

## LAN API

- `GET /health` reports the package `version`, a contract version `api` and
  the build's `capabilities`. `GET /v1/models` lists each model's `n_ctx`,
  `kind`, `role`, and its `tools`, `reasoning` and `embedding` capabilities.
- A thinking model's `<think>` block comes back as `reasoning_content` on
  JSON, SSE and tool-proposal replies, never inside `content`.
- `usage` reports `completion_tokens_details.reasoning_tokens` and
  `prompt_tokens_details.cached_tokens` (prompt tokens the KV prefix reuse
  did not prefill). A client that sends its history append-only pays only for
  the new turn.
- A streamed reply that has been silent for 5 s gets an SSE keepalive
  comment, so a client that disconnects during a long prefill frees the
  session within seconds instead of after the prefill.
- `tool_choice` `required` or a named function always starts with the call.
- A request that fails on the console is reported by its cause: out of
  memory is `503`, a session or backend failure `500`, and only a malformed
  body `400`. The failing route and its cause are logged.

## App

- `settings.json` has one reader and writer, and the app's main page is split
  by concern (no behaviour change).
- SmolLM3-3B and OLMoE chat formats are supported; they are not catalogue
  models.

## Measured on Series S

- Long-prompt prefill with the shipped settings (flash attention on,
  `n_ubatch` 512, f16 KV) is within 3 % of every alternative measured:
  `lfm25-350m` 281 tok/s at 7.2k prompt tokens and 220 tok/s at 14.4k,
  `llama32-3b` 34 tok/s at 3.6k. A 3B dense model at 8k tokens and beyond
  still means minutes before the first token, which is why the catalogue
  contexts stay where they are. Receipts:
  [`2026-11-26-prefill-knobs`](../../bench/results/2026-11-26-prefill-knobs/)
  and [`2026-11-25-nctx-train-bound`](../../bench/results/2026-11-25-nctx-train-bound/).

## Benchmarks

- Host benchmark lanes for standard suites: loglikelihood tasks through
  llama.cpp, and frozen IFEval and GSM8K subsets over any OpenAI-compatible
  endpoint, the console's LAN API included. They are informational and make
  no Series S quality claim.

## Installation and validation

Follow the [installation guide](../install-release.md) and verify the
checksums for the unified MSIX, test certificate and Visual C++ runtime.
Sideload the Developer Mode package. The package keeps the
`GianlucaMazza.xllama` identity, so it updates 1.8.x in place and keeps
LocalState.

The GitHub release attaches the package-bound validation record for Series S:
on `xllama_1.9.0.1963_x64.msix`, the console suite passed 10 of 10 gates, the
LAN API suite 12 of 12 plus the client-disconnect gate, and the D3D12
selftest 24 of 24, after an in-place update that kept LocalState
([validation record](../../bench/results/2026-11-26-v190-series-s-release/)).
