# xllama v1.11.0

Independent project, not affiliated with or endorsed by Microsoft. Xbox and
Xbox Series S|X are trademarks of the Microsoft group of companies.

This Developer Mode release is about clients on the LAN. Agent clients and
Ollama clients now talk to the console natively. A model's sampling values
live in the catalogue, so the app and every client agree on them. Reasoning
can be switched per request, and the largest model gets a context that fits
an agent's prompt. Failures that used to pass as complete replies are now
reported as failures.

## Sampling

- Each catalogue model can carry its own sampling defaults, from its model
  card. `lfm25-1.2b-instruct` uses temperature 0.1, top_k 50 and repetition
  penalty 1.05; `lfm25-8b-a1b` uses 0.2, 80 and 1.05. A paired evaluation on
  Series S found no regression against the previous defaults (and no measured
  gain). Other models keep the previous defaults.
- The layers apply in one order everywhere: the global default, then the
  model's value, then the user's Settings (in the app), then the request.
  `/v1/models` reports each chat model's values with their source.
- **Changed:** Settings now stores only the sampling values you chose. A value
  you never moved follows the model, so on the two LFM2.5 models above the
  app's temperature changes from 0.8 to the card's value unless you had set
  one. A value you had changed is kept. The dialog shows each value's source
  and has **Use the model's sampling values**.

## LAN API

The API contract version stays `1`. Two requests that used to be accepted now
return HTTP 400, as listed under **Changed**.

- **Ollama clients:** `POST /api/chat` and `POST /api/generate` serve the
  native Ollama shapes (NDJSON streams or JSON), on GGUF models. `keep_alive`
  and `GET /api/ps` are supported. The console app keeps priority over the
  model: a request without `keep_alive` leaves it loaded, a lease applies
  only to a model the API loaded, and `keep_alive: 0` on the model the app is
  using returns 409. `options.num_ctx` can lower the context for a request,
  which reloads the model.
- **Reasoning control:** `reasoning_effort` (`"none"` turns reasoning off),
  `chat_template_kwargs.enable_thinking` and Ollama `think` switch reasoning
  per request where the model's template allows it.
  `/v1/models` reports `capabilities.reasoning_control` per model; a switch a
  model cannot honour is a 400.
- **Tool proposals:** a model that does not reason no longer reasons on tool
  requests (qwen3-4b used to spend almost every token reasoning and return an
  empty reply). A replayed LFM2 tool call renders before its result.
  Upstream fixes for LFM2 tool calls with control characters or undeclared
  tools are included.
- **Discovery:** `GET /api/catalog` lists the catalogue a client can download,
  with size, `installed` and `pullable`, so a client no longer needs its own
  copy of the catalogue.
- **Requests:** the `developer` role and text-only content parts are accepted.
  With `stream_options.include_usage`, a stream ends with a separate usage
  chunk, as OpenAI SDKs expect.
- **Changed:** a `response_format` other than text (`json_object`,
  `json_schema`) used to be ignored and is now HTTP 400
  `unsupported_response_format`. `null` and `{"type":"text"}` still work.
  A malformed `stream_options` is also HTTP 400.

## Models

- `lfm25-8b-a1b` opens with an 8192-token context instead of 2048. On Series S
  its peak memory at 8192 is 3647 MB, against a 4864 MB ceiling. A long prompt
  still takes its prefill time, about 60 tokens/s.

## Reliability

- A decode failure inside llama.cpp used to be dropped, and the reply was
  reported as complete. It is now reported: HTTP 500 for a buffered reply, an
  error at the end of a stream, and an error in the app. The session is
  cleared, so the next request starts clean.
- In the app, a reply cut off by a failure stays visibly incomplete and cannot
  be rated.
- A stream that ends in an error now ends in one write, so an Ollama client
  can no longer read a heartbeat after the error.

## Developer Mode installs

- Every package built on main now has a GitHub artifact attestation. To check
  the release package, see
  [Installing a release](../install-release.md) (`gh attestation verify`).
- `xllama-cli` refuses malformed numbers (`64typo`, `1e100` for a float) and
  sampling values outside the LAN API's ranges, instead of running with a
  value nobody chose.
