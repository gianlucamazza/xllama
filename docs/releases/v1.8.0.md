# xllama v1.8.0

This Developer Mode release adds SSE for LAN tool proposals, an optional
D3D12 optimization for GGUF models with projection biases, and fixes for
model downloads and Gemma 4 prompt formatting.

## LAN API

Tool proposals with `stream: true` now receive SSE with the parsed
assistant response, indexed tool calls, finish reason and usage. The server
generates and parses the complete reply before it emits the first event on
the tool path. The previous release returned a single JSON completion for
that request. Clients that support both versions should select the parser
from HTTP `Content-Type`. Tool calls are proposals for the client to handle.

Tool requests that exceed the context window return
`context_length_exceeded`. Tool requests against an ONNX model return
`tools_unsupported_for_model`. See the [LAN API contract](../api-endpoint.md).

## GPU and model handling

- On D3D12, supported F32 projection bias additions can run with their
  projection in the same GPU submission. The option defaults to off. See the
  [GGUF GPU guide](../gguf-gpu-decode.md) for the setting. The
  [Series S feature acceptance record](https://github.com/gianlucamazza/xllama/pull/504)
  covers CI package `1.7.0.1702`. The release package has its own validation record.
- Gemma 4 uses its own chat template across the UI, API, CLI and device
  training. Catalogue downloads check free space, avoid storing model bodies
  in the system HTTP cache and clean up failed partial downloads.
- The SSD MoE work includes a resident CPU reference for the 8B checkpoint
  and parity tooling. The loader integration and console acceptance are
  pending. See [MoE upstream readiness](../research/moe-upstream-readiness.md).

## Installation and validation

Follow the [installation guide](../install-release.md) and verify the
checksums for the unified MSIX, test certificate and Visual C++ runtime.
The package retains the `GianlucaMazza.xllama` identity for in-place updates
from earlier packages with that identity.

The GitHub release attaches the package-bound validation record for Series S.
For the scope of independent Series X testing and the package versions used
in those tests, see [project positioning](../positioning.md).
